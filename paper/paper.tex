\begin{abstract}
Long-term memory frameworks for LLM agents (e.g., Mem0, Zep, Cognee, LangMem) typically assume cloud-scale resources: frontier models, an LLM call on every memory operation, and graph databases.
On commodity laptops running 3B--8B open-weight models, these assumptions cause multi-second stalls, inverted or malformed graph triples, and destructive state updates.
We present \orma, an episode-first memory engine for local language models built around a single rule: \emph{no LLM calls during retrieval}.
\orma{} (i)~organises conversations with a computational Method of Loci whose checkpoints are linked by sequential ``walk'' trajectories;
(ii)~modulates candidate scores with ACT-R power-law recency, Hawkes-style burst intensity and Ebbinghaus-style retention;
(iii)~uses pronoun carry-over heuristics and declarative bracket encoding to compress the injected context; and
(iv)~retrieves through a deterministic four-stage pipeline of Rocchio feedback, Personalized PageRank, an ONNX TinyBERT cross-encoder and Maximal Marginal Relevance.
Extraction of states and events is deferred to an asynchronous background ``sleep'' worker.
On all 1,536 evaluated queries of LoCoMo, zero-LLM \orma{} reaches 28.17\% fuzzy MRR and 46.94\% fuzzy Recall@20 with 414 context tokens (a 98.4\% reduction relative to full context) at 63.8\,ms median latency on a laptop CPU.
With sleep consolidation by Qwen-2.5-3B, Answer-in-Context recall rises from 27.21\% to 31.71\% at 56.2\,ms median latency.
\orma{} is open-source under the Apache-2.0 license.
\end{abstract}

\noindent\textbf{Keywords:} agent memory, local language models, retrieval, Method of Loci, long-term conversation, LoCoMo

\section{Introduction}
\label{sec:intro}

Open-weight small language models (SLMs) such as Qwen-2.5 (3B/7B) and Llama-3.2 (3B) now run privately on personal laptops~\cite{qwen2024qwen25}.
Giving such models memory that persists across weeks or months of conversation, however, remains difficult.
Most published agent-memory systems were designed for unbounded cloud infrastructure, and a sharp gap separates their benchmark claims from the realities of edge deployment.
We identify five recurring obstacles:
\begin{enumerate}
    \item \textbf{The synchronous freeze.} Calling an LLM on every turn to extract entities or update state introduces seconds of latency on a consumer CPU or GPU.
    \item \textbf{Knowledge-graph hallucination.} 3B-class models often fail to emit valid JSON graph schemas and frequently invert subject--object relations or invent associations.
    \item \textbf{Accidental amnesia.} Asking a model to \texttt{DELETE} or \texttt{UPDATE} stored facts causes irreversible loss whenever a situational exception occurs.
    \item \textbf{The negative-attention trap.} Autoregressive attention is drawn to mentioned tokens: telling a small model \emph{``never suggest semicolons in PowerShell''} can increase the chance that it emits semicolons.
    \item \textbf{Context-window exhaustion.} Placing tens of thousands of raw tokens in a 3B model's prompt degrades both accuracy~\cite{liu2024lost} and generation throughput.
\end{enumerate}

Human recall does not require a deep generative pass to remember where one parked or what one's sister is called; it is associative, episodic, and anchored in spatial and temporal context.
Motivated by this, we built \orma{} (from Malayalam \emph{orma}, ``memory'' or ``recollection''), whose design rule is:

\begin{center}
\fbox{\parbox{0.9\linewidth}{\centering
\textbf{The \orma{} axiom.}\\[2pt]
\emph{Episodes are the memory. States are only an index of what is true right now. Retrieval must run with zero LLM generation calls in constant, sub-100\,ms time.}}}
\end{center}

\noindent
Live recall therefore runs entirely on the CPU, using Python with embedded SQLite, hybrid vector--lexical search, graph diffusion and cognitive activation dynamics, while all LLM-based work is moved to an asynchronous, non-blocking consolidation path.

\paragraph{Contributions.}
\begin{enumerate}
    \item An \emph{episode-first} memory design with a strict separation between a zero-LLM synchronous retrieval path and an offline consolidation path (Section~\ref{sec:arch}).
    \item A computational \emph{Method of Loci} that turns conversation streams into topological checkpoints with sequential walk edges, combined with ACT-R, Hawkes and Ebbinghaus activation dynamics (Sections~\ref{sec:loci}--\ref{sec:activation}).
    \item Formal handling of five concrete failure modes of naive memory systems: supersession, attribution bleed, defeasible exceptions, negative priming and relative time (Section~\ref{sec:failures}).
    \item A deterministic four-stage retrieval pipeline (Rocchio $\rightarrow$ Personalized PageRank $\rightarrow$ TinyBERT cross-encoder $\rightarrow$ MMR) that runs on a laptop CPU (Section~\ref{sec:pipeline}).
    \item A full evaluation on LoCoMo (1,536 queries) with exact and fuzzy metrics, per-category analysis, and an open-source implementation (Section~\ref{sec:eval}).
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{LLM agent memory.}
MemGPT~\cite{packer2023memgpt} manages a tiered ``virtual context'' using LLM-driven function calls, in analogy with operating-system paging.
Mem0~\cite{chhikara2025mem0} extracts salient memories with an LLM and updates them through LLM-decided operations; its graph variant stores entity--relation triples.
Zep and its Graphiti engine~\cite{rasmussen2025zep} maintain a temporal knowledge graph.
LangMem~\cite{langmem} and Cognee~\cite{cognee} provide open-source memory layers based on vector search and graph retrieval.
These systems typically issue one or more LLM calls per retrieval and assume strong, often hosted, models.
\orma{} instead restricts LLM use to background consolidation and keeps the retrieval path model-free apart from small embedding and re-ranking networks.

\paragraph{Classical retrieval.}
\orma{} deliberately reuses established components: BM25~\cite{robertson2009bm25}, Reciprocal Rank Fusion~\cite{cormack2009rrf}, Rocchio feedback~\cite{rocchio1971relevance}, PageRank~\cite{page1999pagerank}, cross-encoder re-ranking~\cite{nogueira2019passage,jiao2020tinybert} and Maximal Marginal Relevance~\cite{carbonell1998mmr}.
Its novelty lies in how they are composed over an episodic, loci-structured store and in what is deferred off the critical path.

\paragraph{Cognitive models.}
The Method of Loci~\cite{yates1966art}, ACT-R base-level learning~\cite{anderson1998actr}, Hawkes self-exciting processes~\cite{hawkes1971spectra} and Ebbinghaus's retention curve~\cite{ebbinghaus1885memory} supply the behavioural principles behind \orma's organisation and activation. We borrow these as computational heuristics, not as claims of biological fidelity.

\paragraph{Benchmark.}
LoCoMo~\cite{maharana2024locomo} contains very long multi-session dialogues with question--answer annotations and evidence pointers, and is our evaluation benchmark.

\section{Design Principles: The Ensemble Sweet Spot}
\label{sec:principles}

Human memory relies on biological embodiment, sensorimotor grounding and massively parallel chemical substrates; a laptop is a discrete von~Neumann machine limited by clock cycles, memory bandwidth, caches and matrix-multiplication throughput.
Literal simulations of cognition in software (multi-tier cognitive ontologies, continuous neurosymbolic loops) tend to be brittle and slow on such hardware, whereas brute-force approaches (very long contexts, heavy graph neural networks) overwhelm consumer machines.
We therefore combine three ingredients, taking behavioural \emph{principles} from cognition and implementing them with inexpensive, well-understood mathematics:

\begin{enumerate}
    \item \textbf{Cognitive dynamics.} The Method of Loci~\cite{yates1966art} discretises conversation into topological checkpoints. ACT-R power-law decay~\cite{anderson1998actr}, Hawkes self-exciting bursts~\cite{hawkes1971spectra} and Ebbinghaus-style spaced retention~\cite{ebbinghaus1885memory} shape candidate activation.
    \item \textbf{Pragmatic linguistic heuristics.} Pronoun carry-over rules prevent third-person attribution bleed, and declarative bracket encoding compresses facts into compact, unambiguous strings.
    \item \textbf{Metric-space mathematics.} Dense vector search in SQLite (\texttt{sqlite-vec}) and FTS5 BM25 are fused by Reciprocal Rank Fusion~\cite{cormack2009rrf}; re-ranking uses Rocchio feedback~\cite{rocchio1971relevance}, Personalized PageRank~\cite{page1999pagerank}, a CPU cross-encoder~\cite{jiao2020tinybert} and MMR~\cite{carbonell1998mmr}.
\end{enumerate}

\section{Five Concrete Failure Modes}
\label{sec:failures}

To motivate the architecture, we describe five scenarios in which naive memory pipelines fail on local models. They are qualitative design drivers; Section~\ref{sec:limits} discusses what is and is not evaluated.

\paragraph{S1: State supersession.}
\emph{Session~1:} ``I live in Pune with my sister Asha.'' \emph{Session~5:} ``I just relocated to Bangalore for my new job at Zerodha.''
Naive systems confuse entity bindings, asserting that Asha moved to Bangalore or that the user still lives in Pune.
\orma{} performs entity-attribute supersession in SQLite: the user's active city becomes Bangalore (\texttt{valid\_to = NULL}), Pune is closed (\texttt{valid\_to = t\_relocate}), and Asha's residence is untouched.

\paragraph{S2: Third-person attribution bleed.}
\emph{Session~2:} ``My sister Asha has a severe peanut allergy.'' \emph{Session~7:} ``Suggest some high-protein evening snacks for me.''
A naive model may answer ``Avoid peanut butter toast because of your severe peanut allergy.''
\orma's pronoun carry-over heuristics bind third-person predicates to the named entity (\texttt{entity: Asha}), so recalling preferences for \texttt{entity: User} does not surface the sister's profile.

\paragraph{S3: Defeasible exceptions.}
\emph{Baseline:} ``I drink black coffee every morning at 7\,AM.'' \emph{Exception:} ``I have a terrible sore throat today, so I'm drinking warm ginger tea with honey.''
A system that detects a contradiction on \texttt{(user, morning\_drink)} will permanently overwrite coffee with tea.
\orma{} stores situational overrides next to the canonical baseline through schema-level condition tags:
\begin{align*}
  &[\texttt{user.morning\_drink: black coffee}]\\
  &[\texttt{user.morning\_drink} \mid \text{sore throat} \rightarrow \texttt{ginger tea}]
\end{align*}

\paragraph{S4: Autoregressive mistake recurrence.}
\emph{Directive:} ``Never chain terminal commands with semicolons in PowerShell; use multi-line or \texttt{\&\&}.''
Injecting this as a passive fact draws attention to the token ``semicolons'', which can cause the model to emit it within a few turns.
\orma{} hoists inhibitory rules to Tier~0 at the head of the prompt and encodes them as prohibitions, e.g.\ \texttt{[FORBIDDEN: chaining commands with semicolons]}.

\paragraph{S5: Relative temporal anchoring.}
\emph{Spoken Monday, 12~Oct 2026:} ``My dentist appointment with Dr.~Rao is next Tuesday.'' \emph{Queried 20~Nov:} ``When was my dentist appointment?''
Raw retrieval returns ``next Tuesday!''.
\orma{} anchors every episode to its speech timestamp and resolves relative expressions deterministically (here, taking ``next Tuesday'' to mean the Tuesday of the following calendar week) into an ISO date: \texttt{[EVENT: 2026-10-20: dentist appointment]}.

\subsection{Dual-Path Operation}
\begin{itemize}
    \item \textbf{Live path (synchronous).} Each turn is appended to the lossless \texttt{episodes} table in under 3\,ms. Retrieval executes the four-stage pipeline of Section~\ref{sec:pipeline} on CPU with no LLM call.
    \item \textbf{Sleep path (asynchronous).} When the host has been idle for 120\,s, or 20 turns have accumulated, a background worker invokes a local model (e.g., Qwen-2.5-3B) to extract states and dated events. Each extraction is verified against exact line citations in the stored episodes before being committed to SQLite; unverifiable extractions are discarded.
\end{itemize}
Because episodes are never rewritten, a faulty extraction cannot destroy information, which addresses the accidental-amnesia failure mode.

\subsection{Topological Method of Loci}
\label{sec:loci}
The Method of Loci~\cite{yates1966art} converts linear conversation sessions into spatial ``memory palaces''.
Conversations are grouped into episodic checkpoints (loci); within a locus, consecutive turns are joined by directed \emph{walk} edges, and consecutive loci are linked in session order.
When hybrid search activates a turn, the engine follows adjacent walk edges to restore narrative coherence without loading the entire transcript (Figure~\ref{fig:loci}).

\subsection{Cognitive Activation Dynamics}
\label{sec:activation}
Candidate relevance is modulated by three cognitively inspired terms:
\begin{equation}
  A_i(t) \;=\; \ln\!\Big(\sum_{k=1}^{n_i}(t-t_k)^{-d}\Big)
  \;+\; \sum_{j}\alpha_{ij}\,e^{-\beta\,(t-t_j)}
  \;+\; S_i .
  \label{eq:activation}
\end{equation}
The first term is ACT-R base-level activation~\cite{anderson1998actr}: $t_1,\dots,t_{n_i}$ are the past access times of item $i$ and $d=0.5$ is the power-law decay rate.
The second term is a Hawkes-style self-exciting burst intensity~\cite{hawkes1971spectra}, where earlier events $j$ excite item $i$ with weight $\alpha_{ij}$ and exponential decay rate $\beta$.
$S_i$ is an Ebbinghaus-style spaced-repetition strength~\cite{ebbinghaus1885memory} that grows with successful re-use.

\paragraph{Stage 0: Hybrid candidate generation.}
Dense similarity (\texttt{sqlite-vec}) and lexical BM25~\cite{robertson2009bm25} (FTS5) rankings are fused with Reciprocal Rank Fusion~\cite{cormack2009rrf}:
\begin{equation}
  \mathrm{RRF}(d)=\sum_{r\in\{\text{vec},\,\text{BM25}\}}\frac{1}{k+\mathrm{rank}_r(d)},
\end{equation}
where $k$ is a smoothing constant ($k=60$ in the original formulation).

\paragraph{Stage 1: Rocchio pseudo-relevance feedback.}
To bridge vocabulary mismatch without an LLM, we apply Rocchio feedback~\cite{rocchio1971relevance} in embedding space:
\begin{equation}
  \vq_{\text{exp}}=\alpha\,\vq_0+\frac{\beta}{|\mathcal{D}_{\text{top}}|}\sum_{\vec d\in\mathcal{D}_{\text{top}}}\vec d,
  \label{eq:rocchio}
\end{equation}
with $\alpha=0.7$, $\beta=0.3$ and $|\mathcal{D}_{\text{top}}|=2$ top-ranked documents.

\paragraph{Stage 2: Personalized PageRank.}
We build a bipartite graph $G=(V_E\cup V_S,E)$ in which $V_E$ are entities and $V_S$ are canonical states and loci. Let $M$ be its row-normalised transition matrix and $\vp_0$ the teleport vector seeded from Stage~1 candidates. The stationary distribution is obtained by power iteration~\cite{page1999pagerank}:
\begin{equation}
  \vp^{(t+1)}=(1-\gamma)\,\vp_0+\gamma\big(M^{\top}\vp^{(t)}+\vec w_{\text{dangle}}\big),
  \label{eq:ppr}
\end{equation}
with damping $\gamma=0.85$ and $T=20$ iterations; $\vec w_{\text{dangle}}$ redistributes the probability mass held by dangling nodes so that total mass is conserved. Diffusion lets evidence reach turns in other sessions that share entities or states with the seed hits, which supports multi-hop retrieval without LLM query decomposition.

\paragraph{Stage 3: Cross-encoder re-scoring.}
Bi-encoders embed query and document independently and discard token-level interaction. We re-score the surviving candidates with a 3.2\,MB ONNX-quantised TinyBERT cross-encoder (\texttt{ms-marco-TinyBERT-L-2-v2}, served through FlashRank~\cite{flashrank}) running on CPU~\cite{jiao2020tinybert,nogueira2019passage}:
\begin{equation}
  s_{\text{cross}}(q,d)=\sigma\!\big(\mathbf{w}^{\top}\mathbf{h}_{\text{[CLS]}}([q;d])+b\big),
  \label{eq:cross}
\end{equation}
where $[q;d]$ is the concatenated input pair. A batch is scored in under 3.5\,ms.

\paragraph{Stage 4: Maximal Marginal Relevance.}
To fit the most information into a token budget $B$, candidates $\mathcal{C}$ are selected greedily by MMR~\cite{carbonell1998mmr}:
\begin{equation}
  d^{*}=\arg\max_{d\in\mathcal{C}\setminus\mathcal{S}}\Big[\lambda\,s_{\text{cross}}(q,d)-(1-\lambda)\max_{s\in\mathcal{S}}\mathrm{Sim}(d,s)\Big],
  \label{eq:mmr}
\end{equation}
where $\mathcal{S}$ is the set already selected, $\mathrm{Sim}$ is embedding similarity, and $\lambda=0.7$. Selection stops when $B$ is exhausted.

\section{Experimental Evaluation}
\label{sec:eval}

\subsection{Benchmark and Protocol}
We evaluate on the LoCoMo dataset of Maharana et al.~\cite{maharana2024locomo}, which contains 10 very long multi-session dialogues (up to 35 sessions and several hundred turns each). We use 1,536 evaluation queries from the single-hop, multi-hop, temporal and open-domain categories; the adversarial (unanswerable) category is excluded.
We report two disclosures:
\begin{itemize}
    \item \textbf{Exact metrics:} verbatim equality between a retrieved passage and a gold evidence span.
    \item \textbf{Fuzzy metrics:} an exact match or $\ge 60\%$ token set overlap with the smaller segment ($\min(|W_{\text{ret}}|, |W_{\text{gold}}|) \ge 2$) after standard lowercase and punctuation normalization.
    \emph{Answer-in-Context} measures whether the gold answer string is present in the retrieved context.
\end{itemize}
\textbf{Setup.} All retrieval latencies are measured strictly on a consumer laptop CPU (Windows 11, 16\,GB RAM, host equipped with an NVIDIA RTX 3050 6\,GB GPU), using local \texttt{BAAI/bge-small-en-v1.5} embeddings (384-d, ONNX Runtime) and Ollama serving 4-bit quantised Qwen-2.5-3B (\texttt{qwen2.5:3b}) for background sleep consolidation. \textbf{Modes.} \emph{Zero-LLM} uses only the live path on raw episodes. \emph{With-LLM} first runs sleep consolidation with Qwen-2.5-3B; retrieval itself still makes no LLM call.

\subsection{Analysis}
\begin{itemize}
    \item \textbf{Answer-in-Context improves with consolidation (+4.5 points absolute).} Sleep consolidation extracts compact states and events, so the concise answer is present in 31.71\% of contexts versus 27.21\% in Zero-LLM mode. The gain is largest on single-hop factual queries (20.81\% $\rightarrow$ 36.86\%).
    \item \textbf{Multi-hop retrieval without query-time LLMs.} Personalized PageRank over the entity--state--locus graph yields 41.49\% multi-hop Recall@10 (With-LLM) and 39.72\% (Zero-LLM) without LLM query decomposition.
    \item \textbf{The MRR trade-off.} LoCoMo evidence is annotated at the level of raw dialogue turns. In With-LLM mode, structured states occupy Tiers~1--2 and raw turns fall to Tier~3, which lowers exact-match MRR (12.52\% vs.\ 21.09\%) even though the answer is more often present in the context (31.71\% vs.\ 27.21\%). Rank-based metrics against turn-level evidence therefore under-credit structured memories.
    \item \textbf{Open-domain questions remain hard.} Both modes score below 26\% Recall@10 and below 10\% Answer-in-Context on open-domain queries ($n=92$), which depend on world knowledge beyond the conversation.
\end{itemize}

\section{Discussion}
\label{sec:discussion}
\begin{itemize}
    \item \textbf{Local by construction.} Embeddings (\texttt{fastembed}/ONNX) and vectors reside in a local SQLite file; no data leaves the machine.
    \item \textbf{Predictable latency.} Median retrieval latency is below 64\,ms and p95 below 100\,ms in both modes (Table~\ref{tab:main}), so retrieval does not block interaction.
    \item \textbf{Token economy.} A 414--677 token memory block occupies about 2\% of a 32K-token context window, leaving the remainder for reasoning and tool use on 3B--8B models.
\end{itemize}

\section{Limitations}
\label{sec:limits}
(i)~The five scenarios of Section~\ref{sec:failures} are qualitative design drivers; we do not report controlled experiments for supersession, attribution bleed, defeasible exceptions, prohibition framing or temporal resolution, nor for the claimed $\sim$40\% token saving from bracket encoding.
(ii)~We evaluate retrieval on one benchmark and do not measure downstream answer quality; absolute MRR and recall values are modest, especially on open-domain queries.
(iii)~Latency was measured on a single hardware configuration, and baseline figures in Table~\ref{tab:landscape} are taken from reports, not re-run.
(iv)~With-LLM mode depends on the quality of a 3B extractor; citation verification discards unverifiable extractions, which may reduce recall.
(v)~Hyperparameters ($d$, $\alpha$, $\beta$, $\gamma$, $\lambda$) are fixed and were not tuned per dataset; ablations of individual stages are left to future work.

\section{Conclusion}
\label{sec:conclusion}
We presented \orma, an episode-first cognitive memory engine for local language models. By combining cognitive dynamics, pragmatic linguistic heuristics and classical metric-space retrieval, \orma{} supports associative and multi-hop recall without synchronous generation latency or the risk of corrupting memory through LLM-written updates. On LoCoMo it retrieves with a median latency of about 60\,ms using 414--677 context tokens, and background consolidation raises Answer-in-Context recall. Future work includes stage-wise ablations, end-to-end QA comparison with existing systems, and quantitative evaluation of the five failure scenarios.
